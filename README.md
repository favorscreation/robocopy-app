# Backup Desk 1.3.1

Windows向けの、ボタンで実行する差分バックアップ・復元アプリです。スケジュール・常駐・自動実行はありません。

## 起動

1. `BackupDesk-win-x64.zip` を展開します。
2. `BackupDesk.exe` をダブルクリックします。
3. 「バックアップ」を選び、「フォルダーを追加」でコピー元を追加します。複数のフォルダーを選択できます。
4. 各行の「保存先フォルダー名」と、共通の保存先フォルダーを確認します。
5. 必要に応じて「同時実行数」を選びます。初期値は2です。
6. 「差分を確認」で対象を確認し、「バックアップを実行」を押します。

次回からは保存済みの設定を選び、実行ボタンを押してください。「バックアップを実行」だけでも、その時点の差分を再確認してコピーできます。

Windows x64向けです。.NET 10が対応する、Microsoftのサポート期間内のWindowsバージョン・エディションを利用してください。対応範囲は[MicrosoftのWindows向け.NET対応表](https://learn.microsoft.com/dotnet/core/install/windows#supported-versions)で確認できます。Windows 10 / 11のすべての版を動作保証するものではありません。

.NET 10 LTSを同梱した自己完結EXEのため、追加の.NETランタイムのインストールは不要です。別PCにはEXEをコピーして使えます。設定とログは各PCのユーザーごとに保存します。Windows ARM向けの配布物は今回作成していません。

配布EXEにコード署名は付与していません。

## バックアップのルール

| 状況 | 動作 |
| --- | --- |
| 初回 | コピー元のファイルと空フォルダーを保存先へコピー |
| ファイルが追加された | 追加分をコピー |
| サイズまたは最終更新日時が変わった | 同名の保存先ファイルを上書き（元の日時が古くても対象） |
| サイズと最終更新日時が同じ | コピーを省略 |
| コピー元で削除された | 保存先のファイルは残す |
| 中止・コピー失敗 | コピー中の一時ファイルを破棄し、そのファイルの既存バックアップを残す。完了済みのファイルは残る |
| コピーできない項目がある | 「要確認」またはエラーを表示し、理由をログに記録 |

## 複数フォルダーをまとめてバックアップ

コピー元一覧にフォルダーを追加し、共通の保存先を1つ指定します。各コピー元の**中身**を、保存先配下の「保存先フォルダー名」に分けて保存します。追加した行には、コピー元の末尾のフォルダー名が初期入力されます。「保存先フォルダー名」は行ごとに編集できます。

たとえば共通の保存先を `E:\Backups` にすると、次のように保存されます。

| コピー元フォルダー | 保存先フォルダー名 | 実際の保存場所 |
| --- | --- | --- |
| `C:\Work\Documents` | `Documents` | `E:\Backups\Documents` |
| `D:\Team\Documents` | `TeamDocuments` | `E:\Backups\TeamDocuments` |
| `C:\Photos` | `Photos` | `E:\Backups\Photos` |

上の例では `C:\Work\Documents\note.txt` は `E:\Backups\Documents\note.txt` に保存されます。異なるコピー元に同名のファイルがあっても、別々の保存場所に保管できます。

コピー元を2つ以上指定する場合、「保存先フォルダー名」は全行で必要です。大文字・小文字だけが異なる名前も含め、同じ名前は使えません。コピー元の末尾が同名の場合は、例の `TeamDocuments` のように保存先の名前を変更してください。指定できるのは1つのフォルダー名です。区切り文字を含むパスや `..` などは使えません。

一覧から行を削除しても、元ファイルと既存のバックアップは削除しません。差分一覧・件数・コピー容量は、指定した全コピー元の合計です。保存先の重複や、コピー元と保存先が重なる設定は、コピーを始める前にエラーとして表示します。

旧バージョンのコピー元1つの設定は、そのまま引き継ぎます。この行の「保存先フォルダー名」が空欄なら、以前と同じく保存先直下へ中身をコピーします。コピー元1つの場合は、この空欄の使い方もできます。

旧設定にコピー元を追加する場合、空欄の行にも名前を指定してください。以後、その行のデータは保存先配下の指定名のフォルダーに保存されます。保存先直下にある以前のバックアップは、自動では移動・削除しません。

同名ファイルを更新する方式で、過去の世代は保持しません。フルバックアップ基準の差分アーカイブを毎回作る方式ではありません。

## 複数コピー元の同時実行

バックアップ画面の「同時実行数」で、同時にコピーするコピー元フォルダーの数を1〜8から選べます。初期値は2で、設定ごとに保存します。1を選ぶとフォルダーを順番にコピーします。指定数よりコピー元が少ない場合は、コピー元の数までで実行します。

たとえばコピー元が3つで同時実行数が2なら、最大2つのコピー元を同時にコピーし、終わったものから次のコピー元を処理します。並行しても、各コピー元は設定した別々の保存先フォルダーへ保存されます。

同時実行する単位はコピー元フォルダーです。1つのフォルダー内のファイルは順番にコピーし、差分確認も順番に行う場合があります。復元はこれまでどおり1組のフォルダーずつ行います。

「中止」を押すと、実行中の各処理が停止するまで待って終了します。完了済みのファイルは残ります。一部でコピーに失敗した場合も、他のコピー元を含む処理結果とエラーを確認できます。全コピー元をまとめて取り消す仕組みはありません。

同じドライブに対する読み書きでは、同時実行数を増やすと遅くなる場合もあります。速度を見ながら調整してください。

## フォルダーから復元

1. 「復元」を選びます。
2. 「復元元」にバックアップが入っているフォルダー、「復元先」に戻したいフォルダーを指定します。任意のフォルダー同士を指定できます。
3. 「差分を確認」を押し、追加・上書きされるファイルと件数を確認します。この操作は復元先を書き換えません。
4. 「復元を実行」を押します。確認画面の復元元・復元先・件数を確認して実行します。

復元では、先に差分確認が必要です。実行するのは確認済みの対象です。確認後に復元元・復元先・設定やモードを変更した場合は、もう一度差分を確認してください。バックアップとは別に復元用のパスを保存するため、モードを切り替えてもバックアップのコピー元・保存先は入れ替わりません。

差分確認で対象外・読み取り不能などの「要確認」が1件でもある場合は、復元を実行できません。原因を解消してから、差分を確認し直してください。

| 復元先の状況 | 動作 |
| --- | --- |
| 復元元と同じファイルがない | ファイルを追加 |
| サイズ・最終更新日時・内容のいずれかが異なる | 復元元のファイルで上書き。復元元の日時が古い場合も対象 |
| サイズ・最終更新日時・内容が同じ | コピーを省略 |
| 復元先だけに存在するファイルがある | そのファイルは残す |
| 差分確認後にコピー対象の復元元・復元先が変わった | そのファイルは上書きせず、エラーを記録。差分を確認し直す |
| 中止・コピー失敗 | そのファイルの既存データを残す。完了済みの復元は残る |

復元の差分確認ではSHA-256で内容も比較します。サイズと更新日時が同じでも内容が違うファイルを検出できます。ファイルを読み取って確認するため、大きなデータではバックアップの差分確認より時間がかかります。

復元先には復元元フォルダーの**中身**を同じ階層構造で戻します。たとえば復元元 `E:\Backups\Work`、復元先 `C:\Work` の場合、`E:\Backups\Work\note.txt` は `C:\Work\note.txt` に戻ります。

復元は1組のフォルダーずつ指定します。複数コピー元のバックアップから戻す場合は、対応する保存先配下のフォルダーを「復元元」に選びます。上のバックアップ例なら、`E:\Backups\TeamDocuments` から `D:\Team\Documents` へ復元します。

復元時の上書きでも、過去の世代は保持しません。エラーがある場合は一部だけ復元済みになることがあります。結果と実行ログを確認してください。エクスプローラーで必要なファイルだけをコピーして戻すこともできます。

復元を始める前に対象ファイルを使うアプリやエディターを閉じ、完了まで復元元・復元先を編集しないでください。フォルダー全体をロックする処理ではなく、復元開始後に全ファイルをまとめて元に戻すこともできません。

## 使える場所と制限

- 通常のローカルフォルダー、USBドライブ、アクセス権のあるUNC共有フォルダーが対象です。NAS・ネットワーク共有は環境ごとの確認が必要です。
- コピー元と実際の保存場所に同じ場所や互いの配下は指定できません。複数コピー元では、保存先同士の重複や、あるコピー元の保存場所が別のコピー元と重なる設定も実行前に拒否します。
- リンク・ジャンクション・再解析ポイントを経由するパスは対象外です。OneDriveなどの同期ファイルは、ダウンロード済みでも再解析ポイントがあると除外される場合があります。対象外の表示とログを確認してください。
- バックアップの差分はサイズと最終更新日時で判定します。バックアップでは内容のハッシュ比較をしないため、内容だけ変更してサイズと日時が同じ場合は検出できません。復元ではSHA-256も使って比較します。ファイルシステムによって日時の精度が異なると再コピーされる場合があります。
- 通常のファイルデータと最終更新日時を保存します。アクセス権、所有者、代替データストリーム、ディスクイメージは保存しません。
- ファイルごとに一時ファイルへコピーし、完了してから置き換えます。一時ファイル分の空き容量が必要です。バックアップ・復元全体を一括で取り消す仕組みはありません。
- 開いているファイルはコピーできない場合があります。VSSは使わないため、稼働中のデータベース等には専用のバックアップ手段を使用してください。
- コピー中に追加・変更されたファイルは今回の対象に入らないか、エラーになります。再度実行してください。
- 複数フォルダーのバックアップも、中止・エラーがあっても完了済みのファイルは残ります。全コピー元をまとめて元に戻す仕組みはありません。
- 保存先が同じ複数の実行は排他制御します。複数PCから同じ共有先への同時実行は避けてください。

## 設定・ログ

`%LOCALAPPDATA%\BackupDesk` に `settings.json` と `Logs` を保存します。設定は自動保存し、各設定でコピー元一覧・保存先フォルダー名・共通の保存先・同時実行数と、復元用のフォルダーパスを別々に保持します。不要な古いログはエクスプローラーから削除できます。「ログを開く」から直近の処理内容を参照できます。

設定の削除ボタンは設定だけを消し、バックアップファイルは削除しません。設定を別PCに移す場合は、両方のアプリを終了して `settings.json` をコピーし、移行先のフォルダーパスを確認してください。

## ソースからのビルド

技術構成はC# / .NET 10 LTS / WPF、外部UIライブラリなしです。ソースは `src`、コンソール形式の統合テストは `tests` にあります。アプリのターゲットは `net10.0-windows`、バックアップ処理は `net10.0` です。

ビルドには.NET SDK 10.0.404以降の10.0系を用意してください。`global.json` でSDK 10.0.404を指定し、同じ10.0系の新しいSDKを利用できます。配布用の同梱ランタイムは10.0.15です。ランタイムの更新を配布版に反映するには、再ビルドしてEXEを更新します。

PowerShellでプロジェクトのルートから実行します。

```powershell
.\build.ps1
```

SDKを任意の場所に展開している場合は、`-DotNet 'C:\path\to\dotnet.exe'` で使用するSDKの実行ファイルを指定できます。

統合テスト → 自己完結EXE → `artifacts\BackupDesk-win-x64.zip` の順に生成します。初回のビルドには必要な.NETパックを取得できる環境が必要です。配布物に含む.NETのライセンスと通知は `THIRD-PARTY-NOTICES.txt` を参照してください。

開発時は `dotnet run --project src\ManualBackup.App` で起動できます。テスト用に設定・ログの保存先を変える場合は、環境変数 `BACKUPDESK_DATA_DIR` に専用の絶対パスを指定してください。
